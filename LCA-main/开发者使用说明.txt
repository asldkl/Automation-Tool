1. 项目概述
================================================================================

LCA 是一个面向 Windows 桌面自动化场景的本地工作流工具，提供以下核心能力:

  - 可视化工作流编排: 创建、编辑和执行由多个任务节点组成的自动化流程
  - 图像识别与 OCR: 截图、图像匹配、区域文字识别、多进程 OCR 处理
  - 输入自动化: 鼠标点击/移动/滚轮、键盘输入、录制回放
  - 窗口管理: 窗口选择、绑定、激活、多窗口任务分配
  - AI 辅助: 集成 OpenAI 兼容 API，支持 AI 指令执行和视觉定位
  - YOLO 目标检测: 基于 ONNX Runtime 的本地目标检测
  - 插件系统: 可扩展的插件架构，已内置 OLA(欧拉) 插件适配
  - 多窗口并行执行: 支持多个工作流同时在不同窗口上运行

技术栈: Python 3.10 + PySide6 (Qt 6.9.1) + OpenCV + ONNX Runtime


================================================================================
2. 环境要求
================================================================================

  操作系统:   Windows 10 或更高版本
  Python:     3.10 (推荐使用虚拟环境)
  包管理器:   pip
  管理员权限: 部分功能(全局热键等)需要管理员权限运行


================================================================================
3. 安装与运行
================================================================================

  步骤一: 创建虚拟环境
    python -m venv venv

  步骤二: 激活虚拟环境
    .\venv\Scripts\activate

  步骤三: 升级 pip
    python -m pip install --upgrade pip

  步骤四: 安装依赖
    pip install -r requirements.txt

  步骤五: 启动主程序
    python main.py

  注意事项:
    - 首次安装依赖可能需要较长时间，部分包(如 PySide6、onnxruntime)体积较大
    - 若遇到 opencv-python 安装冲突，可尝试: pip install opencv-python-headless
    - 全局热键功能需要以管理员身份运行

5. 核心模块说明
================================================================================

【app_core/ - 应用核心层】

  app_config.py
    定义应用名称、版本号等常量。当前版本 1.2.6.2。

  app_runtime_bootstrap.py
    应用启动引导模块。负责:
    - 创建 QApplication 实例
    - 初始化主题系统 (QSS样式表)
    - 后台线程初始化插件系统
    - 连接运行时绑定 (热键、系统托盘)
    - 启动 Qt 事件循环并处理优雅退出

  config_store.py
    配置存储管理器。所有配置以 JSON 格式存储。
    功能: 原子写入、损坏文件自动修复、热键配置迁移。
    主配置项: 目标窗口标题、执行模式、输入驱动、截图格式、
    热键 (默认F9/F10)、定时设置、ntfy推送设置、最近工作流列表。

  plugin_bridge.py
    全局插件桥接层。提供便捷函数供任务模块调用:
    - plugin_find_pic()       图像查找
    - plugin_mouse_click()    鼠标点击
    - plugin_key_input_text() 键盘输入
    - plugin_ocr()            OCR识别
    - plugin_capture()        屏幕截图
    等等。当插件启用时自动委托给插件，否则回退到内置实现。
    内含: 并发请求去重、配置缓存 (5秒TTL)、多实例OLA管理。


【plugins/ - 插件系统】

  接口定义 (core/interface.py):
    - IPluginAdapter    插件适配器基接口
    - IImagePlugin      图像插件 (find_pic, find_color, capture)
    - IInputPlugin      输入插件 (鼠标/键盘)
    - IOCRPlugin        OCR插件 (ocr, find_text)
    - PluginCapability  能力枚举 (24种能力)

  插件管理器 (core/manager.py):
    - 单例模式
    - 基于优先级的插件选择
    - 支持热加载/卸载
    - 健康检查机制
    - 自动回退策略

  OLA适配器 (adapters/ola/):
    实现全部插件接口，通过COM或DLL方式加载OLA原生SDK。
    提供图像识别、鼠标/键盘控制、窗口绑定、OCR、找色等能力。


【services/ - 后台服务】

  AI集成 (services/ai/):
    支持 OpenAI Chat Completions 和 Responses 两种协议。
    可配置使用 OpenAI 官方API或任意 OpenAI 兼容端点。
    默认中转站: api.lcaa.top

  MCP服务器 (services/mcp/mcp_openai_server.py):
    基于 stdin/stdout 的 JSON-RPC 服务器。
    暴露工具: list_windows, capture_window, openai_raw,
    openai_find, openai_find_in_window, openai_protocol_probe, click_client

  多进程OCR池 (services/multiprocess_ocr_pool.py):
    管理OCR工作子进程池，通过Socket通信。
    支持 FastDeploy PPOCRv3 CPU OCR引擎。

  多进程图像匹配池 (services/multiprocess_match_pool.py):
    管理图像匹配工作子进程池，架构类似OCR池。


【task_workflow/ - 工作流引擎】

  executor.py (WorkflowExecutor):
    基于 QObject 的工作流执行器，信号驱动架构。
    功能:
    - 解析并执行工作流卡片图
    - 发射 Qt 信号 (执行状态、卡片进度、错误、参数更新)
    - 支持多线程执行
    - 支持子工作流嵌套
    - 变量解析与表达式求值

  workflow_context.py (WorkflowContext):
    工作流上下文数据类，存储:
    - OCR识别结果
    - 图像匹配结果
    - YOLO检测结果
    - AI对话历史
    - 全局变量
    - 共享截图帧


【tasks/ - 任务实现 (27种)】

  详见下一节"任务类型一览"。


【ui/ - 用户界面】

  采用 mixin 模式将主窗口分解为 50+ 个 mixin 类。
  主要组件:
  - 工作流画布: 可视化编辑任务节点和连线
  - 参数面板: 按类别组织 (动作、条件、媒体、选择器、控件、录制、收藏)
  - 控制中心: 多窗口批量操作、定时器管理、工作流分配
  - 选择器: 坐标选取、颜色拾取、OCR区域框选、截图选取


【utils/ - 通用工具】

  截图引擎 (4种):
  - Windows Graphics Capture (WGC)  推荐，Win10 1903+
  - DXGI                           高性能
  - GDI                            兼容性最好
  - PrintWindow                    后台窗口截图

  输入模拟:
  - 标准模式: PyAutoGUI / PyDirectInput / pynput
  - 插件模式: 通过OLA插件注入
  - 工厂模式: 根据配置自动选择

  图像处理:
  - 模板匹配 (OpenCV)
  - 智能图像匹配 (支持多尺度、旋转)
  - YOLO目标检测 (ONNX Runtime + DirectML)

7. 插件系统
================================================================================

【架构】

  插件系统由三层组成:

  1. 接口层 (plugins/core/interface.py)
     定义标准接口，任何插件必须实现这些接口:
     - IImagePlugin:  find_pic, find_color, capture
     - IInputPlugin:  mouse_move, mouse_click, key_input
     - IOCRPlugin:    ocr, find_text

  2. 管理层 (plugins/core/manager.py)
     PluginManager 单例负责:
     - 插件注册与发现
     - 基于优先级的选择策略
     - 热加载/卸载
     - 健康检查
     - 自动回退到内置实现

  3. 适配层 (plugins/adapters/)
     具体插件实现。当前内置 OLA(欧拉) 适配器。

【OLA 插件配置】

  配置文件: plugins/config.json

  {
    "plugin_system_enabled": true,
    "plugins": {
      "ola": {
        "enabled": true,          // 是否启用
        "priority": 10,           // 优先级 (数值越小优先级越高)
        "config": {
          "dll_path": "OLA/OLAPlug_x64.dll",  // DLL路径
          "auto_bind_mode": {
            "display": "normal",  // 显示绑定模式
            "mouse": "normal",    // 鼠标绑定模式
            "keypad": "normal"    // 键盘绑定模式
          }
        }
      }
    }
  }

【使用插件桥接】

  在任务代码中，通过 plugin_bridge 提供的便捷函数调用插件:

  from app_core.plugin_bridge import plugin_find_pic, plugin_mouse_click

  # 自动选择插件或内置实现
  result = plugin_find_pic(screen_image, template_image)
  plugin_mouse_click(x, y)

9. MCP 服务器
================================================================================

MCP (Model Context Protocol) 服务器通过 stdin/stdout 提供 JSON-RPC 接口。

【启动方式】

  python main.py --mcp-server

【暴露的工具】

  工具名称                  说明
  ----------------------    ------------------------------------------
  list_windows              列出所有顶层窗口 (标题 + hwnd)
  capture_window            截取指定窗口客户区，返回 PNG base64
  openai_raw                调用 OpenAI 兼容 API，返回原始文本
  openai_find               对 base64 图像调用 AI，返回目标坐标
  openai_find_in_window     截取窗口 + AI识别，返回客户区坐标
  openai_protocol_probe     探测供应商是否支持指定协议
  click_client              向指定窗口发送后台点击 (客户区坐标)


================================================================================
10. 工作流执行引擎
================================================================================

【核心概念】

  - 工作流 (Workflow): 由多个任务卡片和连线组成的有向图
  - 卡片 (Card): 一个任务节点，包含任务类型和参数
  - 连线 (Connection): 定义卡片间的执行顺序
  - 变量 (Variable): 工作流中的动态数据，支持表达式求值
  - 上下文 (Context): 存储运行时状态 (OCR结果、图像结果、AI对话等)

【执行流程】

  1. 用户在画布上创建任务卡片并连线
  2. 为每个卡片配置参数 (可使用变量)
  3. 点击运行，WorkflowExecutor 开始执行
  4. 按连线顺序依次执行各卡片
  5. 执行过程中发射信号更新UI (进度、状态、错误)
  6. 支持条件分支、随机跳转、子工作流嵌套

【变量系统】

  - 全局变量: 跨工作流持久化存储
  - 运行时变量: 仅在当前执行周期内有效
  - 表达式求值: 支持在参数中使用变量和表达式
  - 变量解析器: 自动解析参数中的变量引用

【多线程执行】

  - 支持在同一个工作流中创建多个执行线程
  - 每个线程可绑定到不同的目标窗口
  - 线程间通过全局变量共享数据


================================================================================
11. 多进程架构
================================================================================

LCA 使用多进程架构隔离关键服务，提高稳定性和性能:

【进程类型】

  1. 主进程 (GUI)
     运行 PySide6 界面，管理工作流编辑和执行调度。
     启动: python main.py

  2. OCR工作进程
     独立进程运行 OCR 推理，通过 Socket 与主进程通信。
     启动: python main.py --ocr-worker

  3. 图像匹配工作进程
     独立进程运行图像模板匹配。
     启动: python main.py --match-worker

  4. 工作流工作进程
     独立进程执行工作流，与主进程隔离。
     启动: python main.py --workflow-worker

  5. MCP服务器进程
     独立进程运行 MCP JSON-RPC 服务器。
     启动: python main.py --mcp-server

【通信方式】

  - OCR/匹配工作进程: Socket 通信 (services/socket_message_utils.py)
  - 工作流工作进程: 进程代理 (task_workflow/process_proxy.py)
  - MCP服务器: stdin/stdout JSON-RPC

【主配置文件 config.json】(运行时自动生成)

  {
    "target_window_title": "",        // 目标窗口标题

    "hotkey_stop": "F10",             // 停止热键
    "schedule_enabled": false,        // 定时执行
    "ntfy_enabled": false,            // ntfy推送通知
    "recent_workflows": []            // 最近打开的工作流
  }

【插件配置 plugins/config.json】

  见第7节"插件系统"。

【工作流文件】

  工作流以 JSON 格式保存，存储在 workflows/ 目录 (已被 .gitignore 忽略)。
  包含: 卡片列表、连线关系、变量定义、卡片参数等。

【日志文件】

  由 logging_runtime.py 管理，支持:
  - 按日期轮转
  - 自动清理过期日志
  - 日志文件位于应用根目录下的 logs/ 目录

13. 子进程启动模式
================================================================================

LCA 的 main.py 支持通过命令行参数启动不同的子进程模式:

  命令                                  模式
  ----------------------------------    --------------------
  python main.py                        主程序 (GUI)
  python main.py --ocr-worker           OCR工作进程
  python main.py --match-worker         图像匹配工作进程
  python main.py --workflow-worker      工作流执行工作进程
  python main.py --mcp-server           MCP JSON-RPC服务器

  子进程模式下不会加载 PySide6，通过创建伪Qt类占位符来避免GUI依赖。

14. 打包发布
================================================================================

LCA 支持两种打包方式:

【Nuitka (推荐)】

  依赖: Nuitka 2.8.9 (已在 requirements.txt 中)
  代码中已包含 sys.frozen 检测逻辑，支持 Nuitka 打包后的路径解析。

  依赖: pyinstaller 6.14.2 (已在 requirements.txt 中)
  代码中已包含 sys._MEIPASS 检测逻辑，支持 PyInstaller 打包后的路径解析。

  示例:
    pyinstaller --onefile --windowed main.py

  注意: 打包时需确保包含以下资源:
  - themes/ 目录 (QSS样式表)
  - plugins/ 目录 (插件配置)
  - resources/ 目录 (资源文件)
  - OLA/ 目录 (如果使用OLA插件，还需包含DLL)

15. 开发注意事项
================================================================================

【代码风格】

  - 项目使用中文注释和中文UI文本
  - 无单元测试文件，无测试框架配置
  - UI层大量使用 mixin 模式，主窗口由 50+ 个 mixin 类组合而成

【关键设计模式】

  - 单例模式: PluginManager
  - 工厂模式: 输入模拟 (input_simulation/)
  - 信号槽机制: 工作流执行器通过 Qt 信号通知UI
  - 桥接模式: plugin_bridge 连接插件系统与任务系统
  - 进程池模式: OCR和图像匹配使用多进程池

【添加新任务类型】

  1. 在 tasks/ 目录下创建新的任务模块
  2. 实现任务执行逻辑
  3. 在 ui/panels/ 中添加对应的参数面板
  4. 在 task_workflow/executor.py 中注册新任务类型
  5. 在 UI 任务选择器中添加入口

【添加新插件】

  1. 在 plugins/adapters/ 下创建新的适配器目录
  2. 实现 IPluginAdapter 接口 (及需要的子接口)
  3. 在 plugins/config.json 中注册新插件
  4. 插件管理器会自动发现并加载

【添加新截图引擎】

  1. 在 utils/ 下创建新的截图模块
  2. 实现统一的截图接口
  3. 在 utils/screenshot_helper.py 中注册新引擎

【调试建议】

  - 日志文件位于 logs/ 目录，按日期查看
  - 子进程问题可通过单独启动对应子进程模式来调试
  - 插件问题可通过修改 plugins/config.json 临时禁用插件来排查
  - 配置文件损坏时 config_store.py 会尝试自动修复

【性能优化点】

  - OCR和图像匹配已使用多进程池
  - 截图池避免重复截图
  - 插件桥接层有请求去重和配置缓存 (5秒TTL)
  - 模板预加载 (template_preloader.py) 减少重复加载开销
  - performance_optimizer.py 提供运行时性能优化
