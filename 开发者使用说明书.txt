1. 项目概述
================================================================================

本工具是《三角洲行动》游戏的日常自动化工具，基于图像识别 + OCR 文字识别技术，支持：
- QQ 登录 + WeGame 快捷登录
- 多账号管理
- 冷却执行（冷却到期自动运行）
- 自动关机
- 邮件通知
- OCR 文字识别（RapidOCR）
- 机器指纹绑定（防复制/防滥用）
- 远程有效期控制（服务器端校验）
- 账号状态实时同步（心跳推送）

3. 模块拆分架构（v1.1.0）
================================================================================

v1.1.0 将 gui_app.py（原约 2926 行）拆分为 7 个文件，采用模块级函数 + app 参数的模式：

----------------------------------------
3.1 设计模式
----------------------------------------

所有子模块使用模块级函数，接收 `app` 参数（App 实例）：

    # gui_app.py
    import automation_runner

    class App:
        def start(self):
            automation_runner.start_run(self)

    # automation_runner.py
    def start_run(app):
        # 直接访问 app.root, app.log_area 等
        ...

优点：无需继承、无循环依赖、函数可独立测试。

4. 防破解保护机制
================================================================================

v1.0.3 采用全新的服务器端验证架构，彻底移除了本地有效期校验：

旧机制（已移除）：
    - 本地 XOR 加密有效期（crypto_utils.py）
    - 多时间源交叉验证（淘宝/苏宁/世界时间API）
    - 本地时间戳防篡改（~/.delta_auto_timestamp.dat）
    - 以上代码已全部删除，不再使用

新机制（v1.0.3）：
    - 机器指纹绑定：通过硬件序列号生成唯一指纹，程序只能在授权电脑运行
    - 服务器端有效期校验：有效期由服务器统一管理，无法本地篡改
    - 双重验证：启动时验证 + 每天首次运行任务时验证
    - 心跳同步：运行时每30秒推送账号状态到服务器

================================================================================
5. 机器指纹机制详解
================================================================================

文件: machine_fingerprint.py

----------------------------------------
5.1 指纹生成算法
----------------------------------------

1. 通过 WMI 获取硬盘序列号：
   命令: wmic diskdrive get serialnumber

2. 通过 WMI 获取主板序列号：
   命令: wmic baseboard get serialnumber

3. 拼接两个序列号（格式: "DISK_SERIAL:BOARD_SERIAL"）

4. 对拼接字符串进行 SHA256 哈希

5. 取哈希值前32个十六进制字符作为机器指纹

降级方案：如果 WMI 调用失败，使用 hostname + MAC 地址作为备用标识

----------------------------------------
5.2 核心函数
----------------------------------------

    get_machine_id() -> str
        返回32位十六进制机器指纹字符串
        示例: "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6"

----------------------------------------
5.3 指纹验证流程
----------------------------------------

客户端启动时：
    1. 调用 get_machine_id() 获取本机指纹
    2. 发送 POST 到 /api/v1/validate，携带 machine_id
    3. 服务器检查白名单 + 有效期
    4. 返回 granted 或 denied

如果验证失败，弹窗显示本机指纹，方便用户复制给管理员

================================================================================
6. 服务器验证流程
================================================================================

----------------------------------------
6.1 启动时验证（server_client.py → validate_with_server）
----------------------------------------

    1. 获取机器指纹
    2. POST /api/v1/validate {"machine_id": "xxx", "current_date": "2026-05-28"}
    3. 如果返回 "granted" → 正常启动
    4. 如果返回 "denied" → 弹窗显示指纹 + 错误原因，退出程序
    5. 如果服务器不可达 → 弹窗显示指纹 + "服务器不可用"，退出程序

----------------------------------------
6.2 每天首次运行验证（automation_runner.py → run_script_main）
----------------------------------------

    1. 检查 _last_validated_date 是否等于今天
    2. 如果不是今天 → 重新调用 /api/v1/validate
    3. 验证通过 → 更新 _last_validated_date
    4. 验证失败 → 弹窗显示指纹，root.destroy() 退出程序

这确保了即使程序长时间不退出，每天也会重新验证一次

----------------------------------------
6.3 验证失败弹窗
----------------------------------------

所有验证失败的弹窗都包含本机机器指纹，格式：
    "机器指纹: a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6"
    "请联系管理员将此指纹添加到白名单"

7. 心跳同步机制
================================================================================

文件: server_client.py（start_heartbeat / heartbeat_loop / send_heartbeat）

----------------------------------------
7.1 心跳线程
----------------------------------------

- 在任务开始时启动，任务结束时停止
- 每30秒发送一次心跳到服务器
- 使用 daemon 线程，不阻塞主程序退出

----------------------------------------
7.2 心跳数据格式
----------------------------------------

POST /api/v1/heartbeat
{
    "machine_id": "a1b2c3d4...",
    "accounts": [
        {"name": "qq1.png", "status": "running"},
        {"name": "qq2.png", "status": "cooling"},
        {"name": "qq3.png", "status": "success"}
    ],
    "is_running": true
}

----------------------------------------
7.3 账号状态值
----------------------------------------

- "running"  - 正在执行自动化任务
- "cooling"  - 跳过（冷却中）
- "success"  - 本账号执行成功
- "failed"   - 本账号执行失败
- "idle"     - 空闲/未执行

----------------------------------------
7.4 状态更新时机
----------------------------------------

在 automation_runner.run_script_main() 中：
    - 开始处理账号 → "running"
    - 冷却跳过 → "cooling"
    - 执行成功 → "success"
    - 执行失败 → "failed"
    - 任务全部完成 → 停止心跳线程

8. 如何管理用户（白名单/有效期）
================================================================================

----------------------------------------
8.1 服务器管理接口
----------------------------------------

所有管理接口需要 ADMIN_SECRET_KEY 认证（Header: Authorization）

1. 添加机器到白名单：
   POST /api/v1/admin/add_to_whitelist
   Body: {"machine_id": "a1b2c3d4..."}

2. 移除机器：
   POST /api/v1/admin/remove_from_whitelist
   Body: {"machine_id": "a1b2c3d4..."}

3. 设置独立有效期：
   POST /api/v1/admin/set_user_expiry
   Body: {"machine_id": "a1b2c3d4...", "expiry": "2026-12-31"}

4. 查看所有用户：
   GET /api/v1/admin/get_all_users

5. 查看机器实时状态：
   GET /api/v1/admin/get_machine_status

----------------------------------------
8.2 有效期管理逻辑
----------------------------------------

- 全局默认有效期：user_data.json 中的 "expiry_date" 字段
- 用户独立有效期：user_data.json → users → {machine_id} → expiry
- 优先级：用户独立有效期 > 全局默认有效期
- 修改有效期只需调用 set_user_expiry 接口，无需重新打包客户端

10. 打包说明（Nuitka）
================================================================================

Nuitka 将 Python 编译为 C 代码后打包，体积更小、性能更好。

----------------------------------------
10.1 安装 Nuitka
----------------------------------------

    pip install nuitka

Nuitka 会自动下载 zig 编译器和 Dependency Walker。

----------------------------------------
10.2 打包模式
----------------------------------------

模式一：onefile（单文件，用于直接分发）
    python -m nuitka --standalone --onefile \
        --enable-plugin=tk-inter \
        --include-data-dir=picture=picture \
        --windows-icon-from-ico=picture/icon/icon.ico \
        --windows-uac-admin \
        --windows-console-mode=disable \
        --output-filename=三角洲自动工具.exe \
        --output-dir=dist_nuitka \
        --assume-yes-for-downloads \
        main.py

    输出: dist_nuitka/三角洲自动工具.exe （约 52 MB）

模式二：standalone（文件夹，用于安装程序分发）
    python -m nuitka --standalone \
        --enable-plugin=tk-inter \
        --include-data-dir=picture=picture \
        --windows-icon-from-ico=picture/icon/icon.ico \
        --windows-uac-admin \
        --windows-console-mode=disable \
        --output-filename=三角洲自动工具.exe \
        --output-dir=dist_nuitka_standalone \
        --assume-yes-for-downloads \
        main.py

    输出: dist_nuitka_standalone/main.dist/ （文件夹，约 195 MB）

----------------------------------------
10.3 Nuitka 与 PyInstaller 对比
----------------------------------------

    特性            PyInstaller       Nuitka
    --------------------------------------------------
    打包体积        约 95 MB          onefile 约 52 MB
    启动速度        较慢              较快
    运行性能        原生 Python       编译为 C，更快
    数据文件访问    sys._MEIPASS      __file__ 定位
    Python 版本     全版本支持        3.14 实验性支持
    编译时间        短                长（需 C 编译）

----------------------------------------
10.4 资源文件定位（resource_path）
----------------------------------------

config.py 中的 resource_path() 同时兼容两种打包方式：

    def resource_path(relative_path):
        if getattr(sys, 'frozen', False):
            # PyInstaller: sys._MEIPASS 指向临时解压目录
            base_path = getattr(sys, '_MEIPASS', ...)
        elif "__compiled__" in dir():
            # Nuitka: __file__ 指向编译后的模块位置
            # onefile 模式下指向临时解压目录
            # standalone 模式下指向 dist 文件夹
            base_path = os.path.dirname(os.path.abspath(__file__))
        else:
            # 开发环境
            base_path = os.path.abspath(".")
        return os.path.join(base_path, relative_path)

注意：Nuitka onefile 模式下，数据文件解压到系统临时目录，
__file__ 在编译模块中指向该临时目录，因此 resource_path 能正确定位。

----------------------------------------
10.5 Nuitka 注意事项
----------------------------------------

1. Python 3.14 仅被 Nuitka 4.x 实验性支持，建议使用 Python 3.13
2. --mingw64 不支持 Python 3.13+，Nuitka 会自动使用 zig 编译器
3. onefile 首次运行较慢（需解压），后续启动会利用缓存
4. standalone 模式更稳定，推荐用于安装程序分发

11. 制作安装程序（Inno Setup）
================================================================================

使用 Inno Setup 6 将打包后的程序制作成 Windows 安装程序。

----------------------------------------
11.1 安装 Inno Setup 6
----------------------------------------

下载地址: https://jrsoftware.org/isinfo.php
安装路径: C:\Program Files (x86)\Inno Setup 6

----------------------------------------
11.2 安装脚本（installer.iss）
----------------------------------------

项目根目录下的 installer.iss 是安装程序配置文件，关键配置：

    [Setup]
    AppId={固定GUID}              # 保持不变，用于覆盖安装识别
    AppName=三角洲行动自动化工具
    AppVersion=1.1.0              # 每次新版本更新
    DefaultDirName={autopf}\三角洲行动自动化工具
    SetupIconFile=picture\icon\icon.ico
    PrivilegesRequired=admin      # 需要管理员权限

    [Languages]
    # 使用简体中文语言包
    Name: "chinesesimplified"; MessagesFile: "compiler:Languages\ChineseSimplified.isl"

    [Files]
    # standalone 模式：将整个 main.dist 文件夹打包
    Source: "dist_nuitka_standalone\main.dist\*"; DestDir: "{app}"; \
        Flags: ignoreversion recursesubdirs createallsubdirs

    [Tasks]
    # 安装时可选：桌面快捷方式、开机自启动
    Name: "desktopicon"; Description: "创建桌面快捷方式"
    Name: "startupicon"; Description: "开机自动启动"

    [Run]
    # 安装完成后可选启动程序
    Filename: "{app}\三角洲自动工具.exe"; Description: "启动程序"; \
        Flags: nowait postinstall skipifsilent

----------------------------------------
11.3 编译安装程序
----------------------------------------

命令行编译:
    "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss

或在 Inno Setup 编辑器中打开 installer.iss，点击 编译 → 执行。

输出: installer_output/三角洲行动自动化工具_安装程序.exe （约 49 MB）

----------------------------------------
11.4 覆盖安装
----------------------------------------

只要 AppId 保持不变，后续版本运行安装程序时会自动检测已有安装：
- 覆盖旧文件（ignoreversion 标志）
- 保留用户数据（配置文件存在 %USERPROFILE% 下）
- 更新开始菜单和桌面快捷方式

每次新版本只需：
1. 更新 installer.iss 中的 AppVersion
2. 重新打包 Nuitka standalone
3. 重新编译 Inno Setup 安装程序

----------------------------------------

14. 常见问题
================================================================================

Q: 如何测试机器指纹验证？
A:
    1. 运行 python machine_fingerprint.py 查看本机指纹
    2. 确保该指纹在服务器白名单中
    3. 如果不在白名单，调用 /api/v1/admin/add_to_whitelist 添加

Q: 服务器不可达时程序会怎样？
A:
    程序会弹窗显示本机指纹和"服务器不可用"提示，然后退出。
    不会降级到本地验证，确保安全性。

Q: 用户说程序打不开怎么办？
A:
    1. 让用户截图弹窗中的机器指纹
    2. 在管理后台调用 add_to_whitelist 添加该指纹
    3. 如果是有效期问题，调用 set_user_expiry 延长有效期

Q: 如何查看哪些机器在线？
A:
    调用 GET /api/v1/admin/get_machine_status，返回所有机器的实时状态。
    超过5分钟无心跳的机器会被标记为离线。

Q: 心跳数据不更新了怎么办？
A:
    1. 检查客户端程序是否还在运行
    2. 检查服务器是否在线
    3. 心跳停止不影响本地自动化功能，只是无法远程监控

Q: 如何修改服务器地址？
A:
    修改 config.py 中 DEFAULT_SETTINGS 的 server_url 字段，重新打包。
    或者让用户在 ~/.delta_auto_settings.json 中手动修改。

Q: 打包后程序无法启动？
A:
    1. 检查所有新模块是否在 hiddenimports 中（PyInstaller）
    2. 检查图片资源是否正确打包
    3. 查看 dist 目录下的错误日志
    4. 确保目标机器能访问服务器

Q: Nuitka 打包后图片资源找不到？
A:
    1. 确认使用了 --include-data-dir=picture=picture 参数
    2. 确认 resource_path() 中 Nuitka 分支使用 __file__ 定位
    3. standalone 模式下确认 picture/ 目录在 exe 同级目录
    4. onefile 模式下数据解压到临时目录，重启后可能需重新解压

Q: Inno Setup 安装后程序无法运行？
A:
    1. 确认安装目录下有 picture/ 目录及所有子目录
    2. 确认以管理员权限运行（电源管理功能需要）
    3. 检查目标机器是否安装了 VC++ 运行库

Q: OCR 识别不工作怎么办？
A:
    1. 检查是否安装了 rapidocr-onnxruntime 依赖
    2. OCR 连续超时 2 次会自动禁用，重启程序可恢复
    3. 检查 OCR 配置是否正确（识别区域、目标文本）
    4. 如果 OCR 引擎初始化失败，程序会自动回退到图像匹配

Q: 资产识别不工作怎么办？
A:
    1. 在设置→全局设置中勾选"启用资产识别"
    2. 点击"设置区域"框选游戏中的资产数值区域（如 "1.2M"）
    3. 点击"测试识别"验证是否能正确识别
    4. 确保游戏画面稳定后再识别（程序会等待 1 秒）
    5. 资产识别使用独立的 RapidOCR 引擎实例（缓存在 automation_runner._ocr_engine）
    6. 注意：资产识别不做 BGR 转换，直接传 numpy 数组给 RapidOCR
